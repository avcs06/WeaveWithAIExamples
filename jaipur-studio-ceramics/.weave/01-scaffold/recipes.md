# Recipes

Each line names a recipe and what it is for. A recipe holds a design-system
component's cases, or a state and hook pattern. Call `get_recipe` with the
name before you use one. Never read `packages/ui` or `packages/recipes` for
them.

- `events`: Event helpers from `@packages/utils/events`: - `composeHandlers(handler, own)`: runs the caller's `handler`, then the component's `own` unless the handler called `event.preventDefault()`. - `preventDefault` and `stopPropagation`: call the event's method, so they work as a handler (`onMouseDown={preventDefault}`). Take React and DOM events.
- `useBoundState`: an editable copy of `value`. Edits show at once and reach `onChange` at once, or with `delay` once edits pause; `flush` sends a waiting edit now. A new `value` from the parent replaces the copy and drops a waiting edit; the echo of the last edit sent doesn't, so typing during a slow save is kept.
- `useControlledValue`: a component's value that its parent controls with `value` and `onChange`, or leaves to the component, starting from `defaultValue`. For a reusable component offering both, as native inputs do. `onChange` runs either way, with any extra arguments the component passes. The setter keeps its identity across renders, like `useState`'s.
- `useDebouncedCallback`: runs a callback once calls pause for `delay` ms, with the last call's arguments. `flush` runs a waiting call now, `cancel` drops it. A call and `flush` return the last run's result, `undefined` before the first: `await saveLater.flush()` waits for a save. A missing callback makes every call do nothing.
- `useDebouncedSearch`: the text of a search field built into a component, as Select's is. Typing shows at once, `onSearch` gets the text after a pause and a cleared search at once; `flush` sends waiting text now, as on Enter. With `search` given, the parent can change the text; `undefined` leaves it to the field. With no `onSearch`, nothing hears it.
- `useDebouncedValue`: a value that follows another once it stops changing for `delay` ms. For work keyed on the settled value in this component, like a request in an effect: one request per pause, not per keystroke. While the two differ, the work is catching up.
- `useDepsChanged`: whether values changed since the last render, read while rendering to adjust state in the same render: an effect would show stale state for a frame, then render again. The first render counts as a change, so one adjustment covers mount and every change after; `trailing` counts only changes after mount.
- `useLatestRef`: the latest committed value of a prop or state, for code running after the render it was made in: past an `await`, or in a listener or timer set up once. Set before layout effects run, so effects and handlers see the new value.
- `useOnChange`: an effect that runs when its deps change, but not on mount. Its cleanup runs before the next change and on unmount, as useEffect's does. For a change from outside the component, like a prop or URL param, that no handler of its own sees.
- `useOnce`: a value made once, on mount, and kept for the component's life, whatever changes later. Example: the filters a page started with, to reset to.
- `usePersistentCallback`: for an event callback like `onChange` that an effect or store holds: a new reference from the parent doesn't rerun the effect, and the latest one still runs. Returns what the callback returns. An optional callback can be passed as is: the result may then be `undefined`.
- `configOrder`: keeps config components in render order. Config components (see configSync) register as they mount, so one that appears later, like a step shown for one event type, would land last. Put `ConfigOrderProvider` inside the owner's `ConfigSyncProvider`, with `onOrder` writing the ids to the owner's store, and call `useConfigOrder(id)` in each config component.
- `configSync`: components that only collect config. They render nothing: they write their props into the store of the component they configure (the owner), which renders from it. For authoring a reusable component with a declarative API, like `<Tour><TourStep … /></Tour>`, so the owner gets its children's settings without reading React children. Pick the hook by what the config is: - `useConfigSync(key, config)`: settings the owner only reads. They return to their initial values on unmount. - `useValueSync(value, defaultValue, apply)`: a value the owner also changes, controlled or not. - `useStoreSync(write, deps?)`: any other write, like registering an item with an action. Undo it on unmount yourself. Without `deps` it writes after every render: for elements, which are new on every render anyway.
- `createContext`: a context for a component tree, with its provider and hook (`[Provider, useValue]`). For values a parent passes down to parts at any depth: a form section's size and lock, a reply's depth, the organizer. Outside any provider the hook returns the defaults.
- `createStore`: one shared store with its actions, outside the component tree. A store hook subscribes by key (`useCart('items')`) or selector (`useCart(({ items }) => items.length)`), and is also the store's API: `getState`, `setState` and `subscribe` work anywhere, outside React too. For state many unrelated components read or change, or that code outside React must reach: a cart, the signed-in user, preferences. Keep actions in the store, and each component subscribes to what it renders.
- `createStoreContext`: a store for each instance of a component, shared by the parts inside it. Returns `[useStore, useStoreContext, StoreProvider]`: `useStore` subscribes like a createStore hook, `useStoreContext()` gives `{ store, useStore }` for reading and writing without subscribing. For a component whose parts read and update the same state, when a page can show several of it: a wizard, an editor, a table. Each provider makes its own store.
- `Accordion`: Sections whose headings open and close their content, like an FAQ. Each `Accordion.Item` is one section. Collapsible is a single one, like a form's advanced settings.
- `Avatar`: a round picture of a person, or their initials without one. Use it beside a name in lists, tables and headers, or on its own for a row of attendees or a profile control.
- `Button`: an action the user takes: save, publish, delete, open a menu. `default` is the main action of a view (one per view), `base` a secondary one, `danger` one that deletes or can't be undone: filled, it is the confirm dialog's button, and on a list row a delete is as quiet as the row's other actions. `look="ghost"` makes any of them quiet, for toolbars and rows, where an action is an IconButton with a tooltip. IconButton is an action shown as an icon alone; PlainButton makes a non-button element, like an info icon or an avatar, act as a button.
- `Card`: a bordered container with padding and gap, for one item's content (an event in a gallery), as a whole-card button, or, in a CardGroup, as a large selectable option with room for a description. CardList lays records out as a column of full-width cards or a grid, with its own Pagination when asked; with `stretchLink`, each card opens its record's page.
- `Checkbox`: one yes/no choice, like consent or a setting; children are its label. CheckboxGroup: several checkboxes answering one question, with its label, help text and error, wired like any form field. Its `className` lays out the checkboxes: a column or a row.
- `Chip`: a compact toggle showing whether it's on, for filters and quick choices that stay visible. A ChipGroup holds 2 to about 8: one choice (`mode="single"`, the default, read as radio buttons) or any number (`mode="multiple"`, read as checkboxes). One chip on its own is an independent on/off filter.
- `Dialog`: a task over the page that waits until it's done or dismissed, like editing a session. `title` names it, children are the body, `footer` holds the actions: nodes, or a function given `close`. openConfirmationDialog: a yes-or-no question, like confirming a delete, awaited from any code; resolves with the result the pressed button sends.
- `Dropdown`: a menu of actions or choices behind a trigger button, with menu roles, focus and keyboard built in (arrows, typeahead, Escape). Write a row as a `Dropdown.Item`, an on/off row as a `Dropdown.CheckboxItem`, one choice of several as a `Dropdown.RadioItem` in a `Dropdown.RadioGroup`. Group rows with `Dropdown.Group`, open a submenu from a `Dropdown.Item` inside `Dropdown.SubMenu`. `showCheckbox` and `showCheckmark` set how checked rows show. The trigger is one focusable element that forwards its props: `Dropdown.Button`, an `IconButton` named for what the menu holds, or for an avatar a `PlainButton` around the Avatar, as the Avatar recipe shows; never an Avatar inside an IconButton. Tab closes the menu, back to the trigger.
- `ErrorBoundary`: shows a fallback in place of its children when they throw while rendering, so one broken part doesn't take down the page. The app root already wraps every page; wrap a part that can fail on its own, like a chart or a feed. The default fallback says something went wrong and offers "Try again".
- `Form`: a form's layout, with Controller, useController and useCanSubmitForm putting the design system's fields under react-hook-form. Form lays out the fields in a column at the form's field width, then its own `error` and its `actions`, the main one last. Call `useForm`, render every field through `Controller`, and spread `{...field}` on the control: it carries the name, value, `onChange`, `onBlur`, a ref that focuses the first invalid field on submit, the `required` mark from `rules`, and the `error` message.
- `FormControl`: a form control's label, box, help text and status message around a control you render yourself. Its children get `controlProps` to spread, last, on the one focusable element.
- `Icons`: LoadingIcon, CheckIcon and MinusIcon, which replace their lucide counterparts so every control draws them the same way. Any other icon comes from lucide-react. Size them with an `icon-size-*` class (body, label, heading, …) to match the text beside them, not lucide's `size` prop.
- `Image`: a picture in a box of a set width and height, such as a product photo, a cover or a logo. The box narrows with its parent and keeps its ratio, so the page doesn't jump while the picture loads. A missing or broken picture leaves the box in place, with an icon in the middle: an image icon, or the `fallbackIcon` you give.
- `Input`: a single-line text field. `onChange` gets the text, not an event. With `delay`, the text shows at once and `onChange` waits for a pause in typing. PasswordInput, SearchInput and NumberInput are the fields for those values; QuantitySelector is a small count stepped with − and + or typed. In a `useForm` form, every field renders through `Controller`, and `{...field}` gives it its name, value, `onChange`, `required` mark, `error` and focus on a failed submit.
- `Link`: text that takes the user to another page: another site, an email (`mailto:`), a phone number (`tel:`) or a file. Inside text it has a dotted line instead of an underline; a link that works as a control, such as a way back, a breadcrumb or a navigation item, is `look="plain"`. In the Next app, a route of the app is the app's NextLink, which looks the same and navigates without reloading the page.
- `Numeral`: a number the user reads and compares, such as a count, a total, a statistic or a table's figures. It sets the digits in the theme's mono font, so they line up in a column and a count that changes doesn't move what sits beside it. A currency sign, a unit or words in it keep the text's font. Size, weight and color come from around it.
- `Pagination`: pages of a long list, like a catalog of sessions. "Showing 11 to 20 of 95 sessions" on the left; a page-size select and the page buttons on the right.
- `Popover`: a panel of your own content opened from a button, like a filter form, a details card or a quick edit. It's a dialog: focus moves in when it opens and back to the button when it closes; Escape, a click outside or tabbing out closes it. `Popover.Button` is its trigger.
- `Radio`: Radio and RadioGroup: one choice from a few visible options, like a ticket type. RadioGroup is the form field, with label, help text and error; each Radio's children are its label. Arrow keys move between radios and choose; the group is one tab stop.
- `ScrollArea`: ScrollArea and FlexScrollArea: a box that scrolls its own content, with scrollbars that show while the content overflows and sit over its edge. ScrollArea is for a box with its own height (`h-*` or `max-h-*` on it). FlexScrollArea is for a flex column, like a side panel or a dialog body: it grows into the room the column leaves it, and scrolls once its content needs more, while the header and footer stay put.
- `Section`: a titled part of a page, like a settings page's "Profile" and "Notifications": a heading, an optional muted description, then the content, with the same sizes and spacing on every page.
- `Select`: Select and MultiSelect: one choice or several from a list. Controlled only; options are `SelectOption` children (map a list, use `SelectGroup` to group). A search field and a clear button are on by default: `allowSearch={false}` removes the field, `allowClear={false}` the button, and `onSearch` searches on the server instead. An option's children draw its row, `renderTrigger` the trigger. In a form, wire it through `Controller`: `{...field}` is all it needs.
- `SidebarMenu`: a sidebar's navigation. Its `header` holds what sits above the list, like the logo, a search or a Create button, its `footer` what sits below it, like the account and sign out, and the rows between them are SidebarMenuItems, one per destination, which scroll when there are more than fit. It fills the height the sidebar gives it, so the sidebar sets that height: the one under the app's header.
- `Switch`: an on/off setting that takes effect as soon as it's flipped, like notifications or a public profile; its children are its label.
- `Table`: rows of records to scan, sort, filter, select and act on. Configure it with parts as children: a `Table.Column` per column, in the order they render, plus the features it needs (`Table.Selection`, `Table.Expansion`, `Table.Reorder`, `Table.Pagination` or `Table.InfiniteScroll`). Sorting and filtering work from a column's `sortable` and `filter` alone: add `Table.Sort` or `Table.Filter` only to set a default or to control the value. Give every column a `width`: on narrow screens the table then scrolls sideways inside itself.
- `Tabs`: views of one subject that share a place on the page, one shown at a time, like a session's details, speakers and feedback. Each `Tab` child is a tab: `title` and icons in the tab list, children as the panel.
- `Tag`: a short label that only informs: a status, a category, a count, or a chosen filter the user removes with its close button (`closable`). The label stays on one line; cut text shows in full on hover.
- `Textarea`: a multi-line text field, like an event's description or a note to attendees. `onChange` gets the text, not an event. With `delay`, the text shows at once and `onChange` waits for a pause in typing. It shows 3 lines by default (`rows`); the user can drag it taller. In a `useForm` form, it renders through `Controller`, and `{...field}` gives it its name, value, `onChange`, `required` mark, `error` and focus on a failed submit.
- `Toast`: toast: a short message at the corner of the screen about something that just happened, like "Session saved", that closes on its own. Call it from anywhere, React or not: it returns the toast's id. updateToast changes a showing toast, dismissToast closes one, clearToasts closes all.
- `Tooltip`: a short hint on hover and keyboard focus, for an element that isn't a control. `Button`, `IconButton`, `Tag`, `Chip`, `Truncate` and the form fields take a `tooltip` prop themselves, so use that on them; `Tooltip` is for any other focusable element, like a `Link`. The trigger must be focusable and forward its props. `UIRoot` already renders the one tooltip: never render a `TooltipProvider`.
- `Truncate`: one line of text that ends in an ellipsis when it doesn't fit, with the full text in a tooltip. Controls already truncate their labels; use it for other single-line text: names, titles, table cells. For your own element, `useTruncation` gives the same cut and tells whether it's cut.
- `Typography`: the text elements of a page, styled by the design system: `Paragraph`, `Caption`, `List` with `ListItem`, `DescriptionList` with `DescriptionTerm` and `DescriptionDetails`, `Quote`, `Code`, `CodeBlock`, `Kbd`, `Mark`, `Separator` and `Time`. - `color` (default, muted, primary or a status) replaces the color the text inherits. Every element but `Separator` takes it. - `font` (ui, display or mono) replaces the font the text inherits. `Code`, `CodeBlock` and `Kbd` are always mono, and `Separator` has no text, so these four don't take it. - Size and line height are fixed: the caption's for `Caption`, the surrounding text's for `Code`, `Kbd`, `Mark` and `Time`, and the body's for the others.
